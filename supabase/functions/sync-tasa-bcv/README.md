# Sistema de Scraping y Almacenamiento Histórico de la Tasa BCV (USD)

Este documento describe la arquitectura, el flujo de resiliencia, la programación automática (`pg_cron` + `pg_net`) y las consultas de conversión histórica implementadas para almacenar y consultar la tasa oficial del Banco Central de Venezuela (BCV).

---

## 1. Esquema en Supabase (`public.tasa_bcv_historial`)

Definido en la migración [`supabase/migrations/32_tasa_bcv_historial.sql`](../migrations/32_tasa_bcv_historial.sql):

| Columna | Tipo | Restricciones | Descripción |
| :--- | :--- | :--- | :--- |
| `id` | `bigint` | `GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` | Identificador único autoincremental. |
| `fecha` | `date` | `NOT NULL UNIQUE` | Fecha calendario (`YYYY-MM-DD`). Garantiza que nunca existan filas duplicadas por día. |
| `tasa` | `numeric(18,8)` | `NOT NULL CHECK (tasa > 0)` | Valor oficial de `1 USD` expresado en Bolívares (`VES`). |
| `fuente` | `text` | `NOT NULL DEFAULT 'scraping-bcv'` | Origen del registro (`scraping-bcv`, `fallback-api-railway`, `fallback-dolarapi`, `manual`). |
| `creado_en` | `timestamptz` | `NOT NULL DEFAULT now()` | Marca de tiempo de inserción/actualización. |

### Políticas RLS (Row Level Security)
- **Escritura (`INSERT`, `UPDATE`, `DELETE`):** Exclusiva para `service_role` (Edge Function y backend administrativo con `SUPABASE_SERVICE_ROLE_KEY`).
- **Lectura (`SELECT`):** Habilitada para roles `authenticated` y `anon` para que tanto el POS/Finanzas como el Storefront puedan convertir montos históricos.

## 2. Lógica de Obtención con Fallback en Cadena (`a -> b -> c`)

Tanto en la Edge Function ([`supabase/functions/sync-tasa-bcv/index.ts`](./index.ts)) como en el helper de Node.js ([`src/lib/bcv.ts`](../../../src/lib/bcv.ts)) se ejecuta el siguiente orden estricto:

1. **Fuente (a) — Scraping directo a `https://www.bcv.org.ve/` (`fuente = 'scraping-bcv'`):**
   - **Selector CSS utilizado:** `#dolar strong` (extrae el texto numérico dentro del bloque `<div id="dolar">`).
   - **Normalización:** Se reemplazan los puntos separadores de miles (`"." -> ""`) y la coma decimal (`"," -> "."`) antes de convertir con `parseFloat`. Se valida estrictamente que `tasa > 0`.
   - ⚠️ **Mantenimiento del Selector:** Si el BCV modifica la estructura HTML de su portal (Drupal), el parser capturará el fallo, registrará un log detallado con el motivo y pasará automáticamente a la fuente `(b)`.
2. **Fuente (b) — Fallback API Pública (`fuente = 'fallback-api-railway'` / `'fallback-dolarapi'`):**
   - Consulta `GET https://tasa-bcv-api-production.up.railway.app/v1/rates/latest` con timeout de `8s` (`AbortController`).
   - El extractor `extraerTasaDePayloadApi` inspecciona de forma segura las propiedades `usd`, `rate`, `promedio`, `tasa`, `data.usd` o `rates.USD`. Si la instancia de Railway no responde, recurre al mirror secundario oficial (`ve.dolarapi.com/v1/dolares/oficial`).
   - Emite un `console.warn` / alerta visible indicando que la tasa del día **no provino de la fuente primaria**.
3. **Fuente (c) — Último Recurso (`tasa_bcv_historial`):**
   - Lee la fila más reciente de `tasa_bcv_historial` (`ORDER BY fecha DESC LIMIT 1`).
   - **Prevención de registros fantasma:** Si se llega al paso `(c)`, **NO se inserta una fila nueva con la fecha de hoy**. De este modo no se contamina la tabla con datos falsos y la consulta histórica arrastrará automáticamente la última tasa válida conocida.

## 3. Limitación Conocida del Certificado SSL del BCV en Deno (Edge Runtime)

- El portal `https://www.bcv.org.ve/` frecuentemente sirve una cadena de certificados SSL incompleta (falta el certificado intermedio de la autoridad gubernamental en los almacenes CA estándar de Mozilla/Deno).
- En **Node.js** (`src/lib/bcv.ts`), se utiliza `new https.Agent({ rejectUnauthorized: false })` exclusivamente para el host del BCV.
- En **Deno / Supabase Edge Runtime**, la API estándar `fetch` no tiene un equivalente seguro por petición a `rejectUnauthorized: false`. Siguiendo buenas prácticas de seguridad, **no se desactiva globalmente la verificación TLS** del runtime Edge: si `fetch` hacia el BCV falla por error de certificado TLS, la Edge Function registra el motivo en los logs y degrada de inmediato a la **Fuente (b)**.

## 4. Programación del Cron Diario (`pg_cron` + `pg_net`) y Zona Horaria

- **Horario objetivo:** `1:00 PM` hora de Venezuela (`America/Caracas`, `UTC-4`).
- **Ajuste a UTC en `pg_cron`:** Dado que `pg_cron` evalúa todas las expresiones en `UTC`, `13:00 (VET) + 4 horas = 17:00 UTC`.
- **Expresión Cron:** `0 17 * * *` (todos los días a las 17:00 UTC).
- **Despliegue de la Edge Function:**
  ```bash
  supabase functions deploy sync-tasa-bcv --no-verify-jwt
  ```
  Se despliega con `--no-verify-jwt` (también fijado en [`supabase/config.toml`](../../config.toml)) porque la invoca `pg_net` internamente desde PostgreSQL enviando el `SUPABASE_SERVICE_ROLE_KEY` en el header `Authorization`.

## 5. Query de Conversión Histórica y Observabilidad

### Conversión de Pagos Pasados
Para convertir un pago realizado en una fecha pasada (incluyendo sábados, domingos o feriados bancarios sin publicación), se utiliza siempre `fecha <= '<fecha_del_pago>' ORDER BY fecha DESC LIMIT 1`:

- **En TypeScript / Backend (`src/lib/bcv.ts`):**
  - `obtenerTasaBcvParaFecha(fechaPago)`
  - `convertirPagoConTasaHistorica({ monto, monedaOrigen, fechaPago })`
- **En SQL (`PostgreSQL`):**
  ```sql
  SELECT * FROM public.obtener_tasa_bcv_por_fecha('2026-10-18'::date);
  ```

### Verificación del Cron y Auditoría de Fallbacks (Observabilidad)
Puedes verificar las ejecuciones del cron y qué días se guardaron por fallback ejecutando en el SQL Editor de Supabase o mediante la RPC `obtener_estado_cron_bcv`:

```sql
-- 1. Verificar que el job está activo en pg_cron
SELECT jobid, jobname, schedule, active, command
FROM cron.job
WHERE jobname = 'sync-tasa-bcv-daily';

-- 2. Revisar las últimas ejecuciones del cron
SELECT d.runid, d.status, d.return_message, d.start_time, d.end_time
FROM cron.job_run_details d
JOIN cron.job j ON j.jobid = d.jobid
WHERE j.jobname = 'sync-tasa-bcv-daily'
ORDER BY d.start_time DESC
LIMIT 15;

-- 3. Identificar días guardados por fallback en lugar de scraping directo
SELECT fecha, tasa, fuente, creado_en
FROM public.tasa_bcv_historial
WHERE fuente <> 'scraping-bcv'
ORDER BY fecha DESC;
```
